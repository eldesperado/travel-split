# HyperFrames Video Inserts Plan

Use video sparingly. The guizang deck already has motion; HyperFrames should create short evidence/method moments that are hard to express on static slides.

## Recommended inserts

### 1. Opening bumper — “Built by a loop”

- **Length:** 6–8 seconds
- **Where:** Before slide 1 or embedded as walk-in loop
- **Visual:** IKB field, mono metadata, large type assembling: `SPEC → PLAN → TEST → CODE → VERIFY`
- **Motion:** Each word snaps into a horizontal loop, then compresses into the final line: `The app was built by a loop.`
- **Purpose:** Sets the thesis before the talk starts.

### 2. Verification cutaway — “Agents need senses”

- **Length:** 10–12 seconds
- **Where:** Before slide 9
- **Visual:** Three channels enter: screenshot / browser click / log line. They route into a central agent block, then return a green/blue verified state.
- **Motion:** Linear data paths, no glow, no sci-fi noise.
- **Purpose:** Makes the eyes/hands/ears metaphor memorable.

### 3. Closing loop — “Faster feedback”

- **Length:** 8–10 seconds
- **Where:** After slide 10 or as social clip
- **Visual:** Loop diagram starts as `prompt → code`, breaks, then reforms as `understand → plan → implement → verify → iterate`.
- **Motion:** Failed line fades; verified loop locks into IKB square.
- **Purpose:** Turns the talk into a reusable mental model.

## Recommended build order

1. Generate only the opening bumper first.
2. Render it as MP4.
3. Test whether it improves the talk pacing.
4. If useful, generate the verification cutaway.

## Notes

- Keep all videos 16:9, 1920×1080.
- Use the same visual identity as the deck: Swiss IKB, no gradients, no shadows, no rounded corners.
- Do not create videos for every slide; that will distract from the presentation.
