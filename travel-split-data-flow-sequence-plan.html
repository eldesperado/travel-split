Travel Split · backend/data-flow plan

The UI stays tabbed. The data layer becomes a small local backend.

The implementation plan is to keep the current Tailwind screens, replace mock data with a shared provider, and put all mutation/persistence behind a tested reducer plus repository. IndexedDB ships now; a SQLite adapter can replace the repository later.

IndexedDB now SQLite later TDD red/green 80% unit coverage Console logs Playwright runtime screenshots
Core idea

React screens do not own business logic.

PeopleScreen, ExpensesScreen, and SettleScreen call provider actions. The provider logs, runs commands through the reducer, persists via repository, then exposes derived balances and settlements.

Persistence

IndexedDB is treated like a local database.

Use normalized stores with tripId even though only one trip is visible. This keeps the future SQLite migration straightforward.

Debugging

Logs appear at boundaries.

Every command and repository operation logs structured console events: start, success, validation failure, and persistence failure.

  3. Red: write reducer tests for add/remove person, upsert/delete expense, blocked delete.
  4. Green: implement command reducer and structured logger wrapper.
  5. Red: write repository contract tests with fake IndexedDB.
  6. Green: implement IndexedDbTripRepository with normalized stores.
  7. Wire: replace mock imports with TripDataProvider selectors/actions.
  8. Verify: unit coverage ≥80%, build, Playwright browser flow + screenshot.
